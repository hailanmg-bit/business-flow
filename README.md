# 业务通（网页版）

乙方业务流程管理 Agent 的**纯前端**版本。覆盖「客户 → 报价 → 合同 → 交付 → 验收 → 开票 → 回款」全流程，**不依赖任何后端服务器**：

- 数据库用 [sql.js](https://github.com/sql-js/sql.js)（SQLite 编译成 WebAssembly）在浏览器内运行，数据存浏览器 IndexedDB；
- AI 调用由浏览器**直连 DeepSeek**（`api.deepseek.com`），Key 只存你本机浏览器的 `localStorage`；
- 全部业务逻辑（意图→动作引擎、三级授权闸门、实体解析、固定口径指标、业务进程推导）都从「业务通」服务端版**逐模块平移**到浏览器 JS，决策确定性不变。

> 数据不出本机。唯一的外网请求，是带着你的 Key 向 DeepSeek 发起的模型调用。

## 功能

- **看板**：业务进程一览（报价/签约/交付/验收/开票/回款/完结），按阶段、客户、停滞筛选；停滞与即将到期高亮。
- **详情**：客户 / 合同 / 报价单的完整档案、履约记录、付款计划与核销、时间线、合同正文。
- **助手**：用一句话查数据、录记录、推进状态、问条款。
  - 指标类问题走**固定口径确定性计算**（转化率、未回款、回款率、停滞单…），不靠模型编；
  - 自然语言录入与状态推进走**三级授权闸门**：一级直接执行（可撤销）、二级出确认卡、三级拒绝（删除/终止/作废/批量/改已生效合同金额）；
  - 任意回答都可**追问口径**（「这个怎么算的？」），系统回放上一句的算法与来源；
  - 临时探索性查询走 NL2SQL，且必须过**只读 SELECT 安全闸**（禁写、禁敏感表、自动 LIMIT）。

## 本地运行 / 发布到 GitHub Pages

### 方式一：本地起一个静态服务器

仓库是纯静态文件，任意静态服务器都行：

```bash
# 任选其一，在仓库根目录执行
python3 -m http.server 8080
# 或
npx serve .
```

然后浏览器打开 `http://localhost:8080`。首次进入会引导你填写 DeepSeek API Key（也可跳过，仅看演示数据）。

> 必须通过 **http(s)://** 访问，不能直接双击 `index.html` 用 `file://` 打开——ES Module 与 WebAssembly 在 `file://` 下会被浏览器拦截。

### 方式二：发布到 GitHub Pages（免费）

1. 把本仓库推到 GitHub（建议 **私有仓库**，因为里面带了演示数据；但即使公开，你的业务数据也只在你浏览器里，不会上传）。
2. 仓库 **Settings → Pages → Build and deployment → Source 选 "Deploy from a branch"**，分支选 `main`（或你用的分支），目录选 `/ (root)`。
3. 保存后等待一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

因为 `sql-wasm.js` 与 `sql-wasm.wasm` 已经随仓库放在 `vendor/` 下（不走 CDN），所以 GitHub Pages 这种纯静态托管也能直接跑起来，离线也能用。

如需自定义域名，在 Pages 设置里填 Custom domain，并（可选）把 `CNAME` 文件加进仓库根目录。

## 隐私说明

- **API Key**：仅存于你浏览器的 `localStorage`（键名 `bizflow_deepseek_key`），只发往 `api.deepseek.com`，不经过任何中间服务器。换设备 / 清缓存需重新填写；可随时在「设置」里更换或删除。
- **业务数据**：存在浏览器 IndexedDB，不上传任何地方。清除浏览器数据会丢失，介意的话请自行导出。
- **模型调用**：走 DeepSeek 官方接口。DeepSeek 允许浏览器跨域直连，无需自建代理。
- 介意把 Key 留在本地？可以随时在「设置 → 数据 → 清空并恢复演示数据」清掉全部本地数据；Key 本身在设置页也能直接删。

## 与原服务端版的关系

本网页版的业务逻辑是从「业务通」服务端版（FastAPI + SQLite + DeepSeek）**逐文件平移**而来，保持同一套确定性规则：

- LLM 只负责「听懂」（意图识别、槽位抽取、条款问答、结果润色），**不负责决定**；
- 风险分级、实体解析、槽位校验、三级拦截、落库、指标口径全部在服务端/浏览器**确定性代码**里完成；
- 因此网页版给出的数字、执行的动作，与服务端版口径一致。

最大的差异：服务端版有账号体系与持久后端，网页版是**单机本地**形态——适合个人随手用、或作为可部署的演示。
